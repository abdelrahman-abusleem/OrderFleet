# ADR-027 — reliability hardening and preserved contracts

Date:2026-10-26. Status: implemented under the approved hardening scope and owner decisions D1–D4/section3.7. Evidence: [progress ledger](../07_PROGRESS_AND_HANDOFF.md), [acceptance matrix](../15_HARDENING_PASS.md).

ADR-014 already defines monetary range/precision. This hardening record uses the next unused identifier027 and does not replace or duplicate014. Existing business decisions and the Order state machine remain unchanged.

## Decisions

- A confirmed Rabbit publish followed by DB completion failure is a crash gap. Leave its lease/failure classification unchanged, log distinctly, and recover by at-least-once redelivery with transactional Inbox deduplication. Confirm durable retry/DLQ copies before ACK. Transport helpers do not take over handler-owned business transactions.
- D1: emit location facts only during an active assignment when movement >=25m OR elapsed >=10s since the last emitted observation. Thresholds are configurable/validated. Persist last-emitted point/time/fence on CourierPosition for restart and concurrency safety; a new assignment initializes a new checkpoint. All accepted observations persist both representations even when suppressed; identical normalized replay performs no save.
- CourierPosition is Courier's PostGIS spatial read projection. Keep both representations. EfCourierStore persists profile, projection, checkpoint and resulting Outbox through the existing single SaveChanges transaction/xmin protection. The checkpoint is not assignment authority. Precise coordinates remain private and absent from unrestricted events/logs.
- D2: retain request idempotency, processed Inbox, financial deduplication/history and business/audit records indefinitely. No new HTTP replay limit. Delete only published Outbox older7d, resolved failures older30d and finished-order attempts older30d; configurable ages cannot fall below those floors. Exact boundaries remain. Require durable consumption evidence; retain cancellation recovery facts until compensation settles. Never delete pending/leased/unpublished/unresolved/active work. Bounded DELETE repeats eligibility outside its key subquery so PostgreSQL rechecks a worker-reopened failure after lock waits. Maintenance failure does not redefine business readiness.
- Recovery retains persisted UTC deadlines/API expiry guards. Empty sweeps back off to10s by default and reset on work; item retry/classification remain. Six actual EF queries were explained over100000 orders/jobs. Only a large Payments sequential scan justified a partial covering index. Small empty diagnostic scans and already-indexed paths did not justify speculative indexes. [Before](../evidence/recovery-query-plans-before.txt) and [after](../evidence/recovery-query-plans-after.txt) timings are observations, not production SLAs.
- D3: standalone Order persistence may still reference a missing Courier. Warn with OrderId only and preserve leniency; application dispatch still requires real profiles/current fences.
- D4: keep IClock as SystemClock's TimeProvider wrapper. Composition owns registration; no broad replacement/testing package. Section3.7 keeps ArgumentException types/messages/mappings and exact assertions. Private validation/pricing helpers preserve one caller enumeration, validation order and arithmetic.
- DomainException belongs to Domain.Common across aggregates; implementation/HTTP classification unchanged. Fixed vocabularies use identical string constants. Three ordering capabilities share one scoped EF store. OrderTransitionEffects stages courier→job→history per fact in the existing transaction; OrderLocking preserves load/xmin versus tracked-root lock-only operations. Candidate SQL retains distance/Id ordering and FOR UPDATE OF c SKIP LOCKED.
- Realtime remains single-instance under ADR-022. Future Redis backplane/equivalent needs negotiated-transport affinity plus per-replica event fanout/live local checks or a distributed subscription registry. A competing Rabbit queue and a backplane alone do not distribute local authority state. Verify multi-replica reconnect, revocation, expiry, stale/duplicate sequences, private location filtering and outages before scaling. No backplane is implemented here.
- Forwarded client/scheme headers require explicit proxy/network trust and one-hop handling; default disabled, no /0 trust. Duplicate registration timing remains a documented tradeoff. No broad auth/payment/recovery rewrite is implied.

## Consequences and verification

Unbounded request/Inbox retention grows storage; expiration needs a separate approved production replay/retention policy. GPS suppression reduces messages while retaining current state, but can delay notifications. Conservative cleanup guards can retain published facts beyond nominal ages. Failed cleanup does not force a business-service restart loop.

Additive migrations:20261026115510_ThrottleCourierLocationEvents (three nullable checkpoint fields/check) and20261026122439_IndexPendingCaptureRecovery (measured partial index). Historical migrations unchanged. Missing historical checkpoints initialize on the next assigned observation. Live-table migration scheduling is an operator responsibility; this pass applies only to disposable databases/local smoke stacks.

Tests added in this pass cover capture/cancel interleavings; GPS replay/checkpoint boundaries/rollback; publish versus completion failures; failed mandatory retry publication/redelivery; retention boundaries/batches/protected identities/reopened-failure locks; proxy spoofing; cancellation authority; vocabulary round trips; scope/clock lifetimes; and safe hub logs. Exact counts and final migration/smoke evidence belong to the ledger. No package upgrade, push/deployment, GUID generation change or backplane is included.
